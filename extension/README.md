# 브라우저 확장 (스파이크)

`DESIGN.md` 는 이 경로를 부록 A 에서 **미검증** 상태로 기각했다. 기각 근거가 둘 다
약해서 다시 본다:

1. "Vivaldi 내장 캡처가 모든 페이지에서 실패" — 그건 Vivaldi 의 스크린샷 기능이지
   확장의 `chrome.tabs.captureVisibleTab` 이 아니다. 다른 API 다
2. "확장 경로는 만화 읽을 때만 크롬을 강제할 위험" — Vivaldi 는 Chromium 기반이라
   크롬 확장이 그대로 돈다. 브라우저를 바꿀 필요가 없다

## 이 스파이크로 확인하려는 것

**셋뿐이다. 되면 M3~M6 계획을 갈아엎을 근거가 되고, 안 되면 30분 잃고 만다.**

1. 뷰어 페이지에서 `captureVisibleTab` 이 실제로 픽셀을 주는가
   (comic-walker 의 SpeedBinb 타일 렌더링, 각 사이트의 canvas 보호)
2. 그 픽셀이 `mtl-service` 를 왕복해 원문·번역이 돌아오는가
3. **좌표가 맞는가** — 박스가 말풍선 위에 정확히 얹히는가

3번이 핵심이다. OS 캡처 경로는 화면 좌표를 역산해야 하고 `DESIGN.md` §6 이 그 오차
예산(±4px)을 통째로 쓴다. 확장은 DOM 이 뷰어 사각형을 직접 알려주므로 **추측이 없다.**

## 쓰는 법

**1. 서비스를 띄운다** (별도 터미널)

```
uv run mtl-service
```

`service.toml` 이 `dev_bind_loopback = true`, `auth_disabled = true` 여야 한다
(지금 기본값이다). 포트는 8788.

**2. 확장을 로드한다**

Vivaldi/Chrome 에서 `chrome://extensions` → 우상단 **개발자 모드** 켜기 →
**압축해제된 확장 프로그램을 로드** → 이 `extension/` 폴더 선택.

**2-1. 서비스 주소 확인** — 확장 옵션 화면(`chrome://extensions` → 이 확장 → 세부정보
→ 확장 프로그램 옵션)에서 주소를 본다. 기본값은 `http://<서비스-머신-tailscale-주소>:8788/read`
(서비스 머신 의 Tailscale 주소)다.

**루프백이 기본값이 아닌 이유:** 서비스는 Tailscale 인터페이스에만 바인딩한다
(`DESIGN.md` §4.4 — `0.0.0.0` 폴백 없음). 서비스가 도는 그 머신의 브라우저에서도
`127.0.0.1` 로는 못 붙는다. Tailscale 주소 하나면 맥북·윈도우 양쪽에서 그대로 돈다.

**3. 만화 페이지에서 `Alt+Shift+M`** (또는 툴바 아이콘 클릭)

뷰어를 못 찾거나 엉뚱한 곳을 잡으면 **`Alt+Shift+D`** 로 직접 드래그해서 고른다.
화면이 어두워지고 드래그한 사각형만 밝게 남는다. Esc 로 취소.

자동 탐지(`probeViewer()`)는 `img`/`canvas` 중 200px 이상인 것을 기하로 묶는 휴리스틱
이라 반드시 틀리는 사이트가 나온다 — 뷰어가 작은 타일로 쪼개져 있거나, 배경 이미지로
그려지거나, 광고가 만화보다 크거나. 그때 손으로 집을 수단이 없으면 그 사이트는
통째로 못 쓴다.

**글자가 있는 영역을 골라라.** 그림만 있는 칸을 고르면 검출기가 양식화된 획(효과음
로고 등)을 글자로 보고 OCR 이 헛것을 뱉는다. 실측에서 그림만 있는 칸을 골랐더니
「ロスロネスロの」 같은 것이 나왔고 번역도 15초를 썼다.

좌상단에 진행 상태가 뜨고, 검출된 영역에 박스가 그려진다.

- **초록 실선** — 말풍선 (`is_bubble = true`)
- **파랑 점선** — 효과음·배경 텍스트
- **주황** — 번역 도착. 스트리밍이라 하나씩 채워진다

**라벨은 마우스를 올려야 보인다.** 전부 펼쳐 놓으면 아래쪽 말풍선을 가려서 원문을
못 읽는다 (실측). 전체 토글은 `Alt+Shift+L`.

**효과음과 잡문은 자동으로 숨는다.** 번역 모델이 원문을 보고 분류한 `kind` 를 쓴다
(`DESIGN.md` §8.4) — 서버의 `is_bubble` 이 아니다. 그쪽은 스크린톤 배경 위 말풍선을
오판해서 대사를 통째로 날린다 (`DEVLOG.md`).

| `kind` | | 기본 |
|---|---|---|
| `dialogue` | 인물의 말·생각 | 보임 |
| `narration` | 나레이션 상자, 화 제목, 간판 | 보임 |
| `sfx` | 효과음 | **숨김** |
| `extra` | 사이트 UI, 광고, 판권 | **숨김** |

숨긴 것을 보려면 `Alt+Shift+S`. 상태줄에 몇 개를 숨겼는지 나온다.

## 실측 결과 (2026-07-27, sunday-webry)

**좌표는 정확하다.** 번역 라벨이 해당 말풍선에 정확히 얹혔다 —
`DESIGN.md` §6(좌표 역환산 ±4px 예산)과 §5.4(Retina·DPI 보정)가 필요 없다는 실증.

**뷰어가 2×2 격자일 수 있다.** sunday-webry 는 세로 스크롤로 펼침면을 위아래로 쌓아
화면에 4페이지를 보여준다. 그래서 씨앗을 **면적 최대**가 아니라 **뷰포트 중앙 최근접**
으로 고르고, 같은 행(= 한 펼침면)만 잡는다. 4페이지를 한 번에 보내면 `order.py` 의
펼침면 분할(2페이지 가정)이 엉키고 §8.4 의 "페이지당 1회 호출" 전제도 무너진다.

## 봐야 할 것

| 증상 | 뜻 |
|---|---|
| "뷰어로 볼 만한 요소를 못 찾았다" | 뷰어가 `<img>`/`<canvas>` 가 아니다. `probeViewer()` 를 고쳐야 한다 |
| 상태만 뜨고 박스가 없음 | 캡처는 됐는데 검출이 0개. 잘린 영역이 틀렸을 수 있다 |
| 박스가 통째로 어긋남 | 좌표 환산 문제. `dpr`/`scale` 을 확인 |
| 박스가 몇 px 어긋남 | 뷰어 사각형이 실제 만화 영역보다 크다 (여백 포함) |
| 캡처가 검게 나옴 | 이 경로가 막힌 것이다. **기각 근거가 된다** |

`chrome://extensions` 의 「서비스 워커」 링크를 누르면 콘솔에서 예외를 볼 수 있다.

## 스파이크라서 안 한 것

- **L1/L2/L3 오버레이** (§7.3) — 박스와 라벨만 그린다. 조판·마스크 채우기 없음
- **페이지 전환 자동 감지** (§5.1) — 단축키로만 돈다
- **`prev_page_phash` 문맥** (§8.4) — 항상 null 로 보낸다
- **설정 UI** — 서비스 주소·토큰이 `background.js` 상단 상수다
- **프로필별 `capture_region`** (§12) — DOM 에서 뷰어를 찾으므로 필요 없을 수도 있다.
  그게 이 스파이크가 답할 질문 중 하나다

| DESIGN 절 | 확장에서는 |

## 다른 기기에서 쓰기 (맥북 등)

서비스는 서비스 머신 한 곳에서만 돈다 (GPU가 거기 있다). 다른 기기는 **확장만** 깔면
된다 — 캡처와 오버레이는 브라우저가 하고 연산은 전부 원격이다.

**필요한 것은 셋이다.**

1. **서비스가 Tailscale 에 바인딩** — `service.toml` 의 `[server].dev_bind_loopback = false`
   (2026-07-27 적용). `bind_tailscale_only = true` 라 Tailscale 주소를 못 찾으면
   기동을 거부한다
2. **윈도우 인바운드 허용** — 기본 정책이 차단이라 규칙이 없으면 조용히 막힌다.
   `mtl-service (Tailscale)` 규칙을 만들어 뒀다: Tailscale 인터페이스 · Private 프로필 ·
   TCP 8788 · 이 프로젝트의 `.venv\Scripts\python.exe` 로만 좁혀 놓았다.
   지우려면 `Remove-NetFirewallRule -DisplayName 'mtl-service (Tailscale)'`
3. **확장의 `host_permissions`** — `manifest.json` 에 `http://<서비스-머신-tailscale-주소>:8788/*` 가
   있어야 한다. 주소를 바꾸면 여기도 같이 고치고 확장을 다시 읽어야 한다
   (옵션 화면만 바꾸면 요청이 CORS 로 막힌다)

**인증은 아직 꺼져 있다** (`auth_disabled = true`). tailnet 안이라 외부에는 안 열리지만
같은 tailnet 의 다른 기기는 전부 붙을 수 있다. 켜려면 `service.toml` 의
`auth_token` 을 정하고 `auth_disabled = false` 로 바꾼 뒤 확장 옵션 화면에 같은 값을 넣는다.

**Retina(dpr=2)는 아직 검증 안 됐다.** 좌표 계산은 `devicePixelRatio` 를 타고 들어가
있지만(`background.js` 의 `cropAndNormalize`, `content.js` 의 `toCss`) 실제로 2배
화면에서 돌려 본 적이 없다. 맥북 테스트의 가장 큰 수확이 이것이다 — 라벨이 말풍선에서
**절반만큼 밀리면** dpr 을 두 번 곱하거나 빠뜨린 것이다.


## 박스 우클릭 메뉴

검출·OCR·번역 중 하나만 틀려도 박스 하나가 통째로 쓸모없어진다. 페이지를 통째로
다시 읽는 것 말고 **그 박스만** 손볼 수단이 필요하다.

| 항목 | |
|---|---|
| 원문 보기 / 번역 보기 | 그 박스만 원문(일본어)으로 되돌린다. 번역이 이상할 때 원문을 확인한다 |
| 다시 읽기 | 그 영역만 잘라 다시 보낸다. **캐시를 건너뛴다** |
| 크기 조정 | 모서리를 끌어 bbox 를 맞춘다. 놓으면 바로 다시 읽는다 |
| 지우기 | 오검출 박스를 치운다 |
| 걸러진 것 보기 | 숨긴 효과음·잡문을 표시 (`Alt+Shift+S` 와 같다) |

**「다시 읽기」와 「영역」은 캐시를 건너뛴다.** 사용자가 굳이 다시 시키는 것은 지난
결과가 마음에 안 들어서다. 캐시를 주면 예전에 잘못 읽은 것을 그대로 돌려준다 —
실제로 그 일이 났다 (`DEVLOG.md`).


## 음성 읽기

패널 **「음성」** — 읽기 순서대로 소리내어 읽는다. 지금 읽는 박스가 하늘색으로
표시되므로 어디를 읽는지 눈으로 따라갈 수 있다. 다시 누르거나 `Esc` 로 멈춘다.

우클릭 **「읽어주기」** — 그 박스만.

**브라우저 내장 `speechSynthesis` 를 쓴다.** 서버 TTS 는 모델·GPU·지연이 붙는데
개인용 읽기 도구에 그만한 값을 치를 이유가 없다. 비용 0, 서버 변경 0 이고 맥에는
한국어(Yuna)·일본어 음성이 이미 깔려 있다.

**읽는 것은 원문(일본어)이다.** 번역은 눈으로 보면 되고 귀로 듣고 싶은 것은 원문이다 —
말투·억양은 번역문이 아니라 원문에 있다. 눈은 한국어, 귀는 일본어.
OCR 이 원문을 못 남긴 박스만 번역문으로 떨어진다.

**여성 음성을 우선한다.** Web Speech API 에는 성별 필드가 없어서 이름으로 고른다
(`content.js` 의 `FEMALE_VOICES`). macOS 기본은 일본어 Kyoko, 한국어 Yuna 다.
목록에 없는 음성을 쓰고 싶으면 그 상수에 이름 일부를 추가하면 된다.

음성이 안 나오거나 남성으로 나오면 시스템에 그 음성이 깔려 있는지 볼 것
(macOS: 시스템 설정 → 손쉬운 사용 → 말하기 → 시스템 음성 → 사용자화).
Kyoko 는 기본 포함이지만 고품질 버전은 따로 내려받아야 할 수 있다.


## 캐시 지우기

같은 페이지를 다시 읽으면 캐시가 걸려 **번역 비용이 들지 않고 문장도 그대로**다.
결과가 이상할 때만 지운다. 범위가 둘이다.

| | 어디서 | 무엇을 |
|---|---|---|
| **그 페이지만** | 패널 「갱신」 | 보고 있는 페이지의 캐시를 지우고 다시 읽는다. 새 결과는 저장 |
| **전부** | 옵션 화면 「캐시 전부 지우기」 | 되돌릴 수 없다. 다시 읽을 때 번역 비용이 새로 든다 |

거의 항상 **「갱신」**이면 된다. 전체 지우기는 서버 쪽 처리를 크게 바꿔서 예전 결과가
전부 못 쓰게 됐을 때만 쓴다.

**페이지 단위 지우기는 조회와 같은 퍼지 기준을 쓴다.** 정확 일치만 지우면 캡처가
매번 몇 비트씩 달라서 정작 보고 있는 페이지의 행이 안 지워진다.

## 윈도우에서

기능은 전부 같지만 **일본어 TTS 가 기본으로 안 깔려 있다** (실측: Heami/ko-KR,
Zira·David/en-US 뿐). 음성은 원문(일본어)을 읽으므로 그대로면 무음이 된다.

그래서 **일본어 음성이 없으면 번역문(한국어)을 읽는다.** 상태줄에
`일본어 음성이 없어 번역문을 읽는다` 가 뜬다.

일본어로 듣고 싶으면 설치할 것:
**설정 → 시간 및 언어 → 언어 및 지역 → 일본어 추가 → 언어 옵션 → 음성 인식/음성**
(Haruka·Nanami·Ayumi 가 목록에 들어오면 자동으로 잡힌다).


## 화면이 깜빡이거나 박스가 어긋날 때

**박스는 뷰어를 따라간다.** 오버레이는 `position: fixed` 라 뷰포트에 붙어 있어서,
그냥 두면 스크롤할 때 만화만 움직이고 박스는 남아 엉뚱한 그림 위에 덕지덕지 쌓인다.

박스를 하나씩 다시 계산하지 않는다 — `#mlr-boxes` 에 **변환 하나**만 건다. 읽을 때의
뷰어 사각형을 지금 사각형으로 보내는 변환이라 스크롤(이동)과 확대(배율)를 한 번에
처리하고 비용이 거의 없다.

**휠은 자동 감지 신호에서 뺐다.** 스크롤은 페이지 넘김이 아닌 경우가 대부분인데,
확인할 때마다 캡처하느라 오버레이가 숨었다 돌아와 깜빡였다. 박스가 뷰어를 따라가므로
스크롤해도 결과가 어긋나지 않아 다시 읽을 이유가 없다. 스크롤로 새 페이지가 나타나는
뷰어는 DOM 변화가 같이 오므로 그쪽 신호에 잡힌다.

캡처 직전 오버레이가 잠깐 숨는 것은 없앨 수 없다 — 박스와 버튼이 스크린샷에 찍히면
검출기가 그걸 글자로 읽는다. 대신 **읽는 횟수 자체를 줄였다.**


## 「다시 읽기」는 그 영역만 다시 부른다

전체 페이지를 다시 번역하지 않는다. 그 박스 둘레만 잘라 보내므로 비용도 그만큼이다.
다만 검출기에 문맥을 주려고 **3배 넓게** 잘라 보내기 때문에(위 「영역 선택」 절),
고른 범위 밖의 말풍선 몇 개가 같이 번역된다 — 화면에는 안 보이지만 그만큼은 낸다.

**결과가 도착한 뒤에 옛 박스를 지운다.** 먼저 지우면, 다시 읽어서 아무것도 안 나올 때
(그 영역에 글자가 없거나 검출이 실패할 때) 원래 박스마저 사라져 손해만 본다.
못 찾으면 원래 박스를 되돌리고 상태줄에 알린다.


## 캐시 지우기 세 갈래

| | 어디서 | 지우고 나서 |
|---|---|---|
| **갱신** | `Alt+Shift+R` · `Shift`+「번역」 · 「⋯」→갱신 | 바로 다시 읽는다 |
| **캐시삭제** | 「⋯」→캐시삭제 | **다시 읽지 않는다.** 다음에 그 페이지를 열 때 새로 읽는다 |
| **전부 지우기** | 옵션 화면 | 되돌릴 수 없다 |

「갱신」과 「캐시삭제」를 나눈 이유: 결과가 이상한데 **지금 당장 다시 읽고 싶지는
않을 때**가 있다 — 번역 비용이 드니까. 지워만 두면 나중에 알아서 새로 읽는다.

캐시 키가 화면 픽셀의 해시라, 「캐시삭제」도 **지금 화면을 한 번 찍는다** — 무엇을
지울지 알아야 하기 때문이다. 번역은 하지 않으므로 API 비용은 들지 않는다.


## 박스가 뷰어를 따라가는 방식

박스마다 **뷰어 기준 비율**(`dataset.n`)을 들고 있다가, 화면이 바뀌면 절대 좌표를
다시 낸다. 스크롤·확대·전체화면·창 크기 변경이 전부 같은 경로로 처리된다.

**예전에는 `#mlr-boxes` 에 변환(transform) 하나를 걸었는데** 전체화면처럼 배율이 크게
바뀌면 **라벨 글자까지 같이 확대·축소돼** 읽을 수 없었다. 비율 재계산은 박스만 커지고
라벨은 항상 같은 크기로 남는다.

전체화면 전환 때 SpeedBinb 는 타일을 새로 만든다 — 기억해 둔 뷰어 요소가 사라지면
다시 찾는다.

## 손으로 한 작업이 페이지를 떠나도 남는다

「영역」으로 더한 박스와 「지우기」로 없앤 박스는 페이지별로 저장된다
(`chrome.storage.local`, 최근 200페이지).

**좌표는 뷰어 사각형 기준 비율로 저장한다.** 화면 픽셀로 저장하면 창 크기나 확대
배율이 바뀌는 순간 전부 어긋난다.

기준 사각형은 `viewerRect()` 로 **매번 직접 잰다.** `ctx.rect` 를 쓰면 안 된다 —
그 값은 "이번에 잘라 보낸 범위" 라, 부분 읽기(영역 지정) 때는 뷰어가 아니라 작은
크롭 사각형이다. 저장은 부분 읽기 끝에 하고 복원은 전체 읽기 끝에 하므로, 그대로
쓰면 기준이 서로 달라져 좌표가 통째로 어긋난다.


## 잠깐 숨기기

**`` ` ``(백틱) 키를 누르고 있는 동안** 박스와 상태줄이 사라진다. 손을 떼면 돌아온다.
박스가 말풍선을 가릴 때, 번역이 맞는지 원문 획을 볼 때 쓴다.

토글이 아니라 **누르고 있는 방식**인 이유: 잠깐 보는 용도에는 "다시 켜는 것" 을
기억할 필요가 없는 쪽이 손이 덜 간다. 오래 감춰 두고 싶으면 「⋯」→「숨김」 으로 고정한다.

감춰도 패널은 흐릿하게 남는다 — 되돌릴 곳을 잃으면 안 된다.

`display:none` 이 아니라 `visibility` 를 쓴다. 되돌릴 때 레이아웃을 다시 잡으면
라벨 배치(`layoutLabels`)가 흐트러진다.


## 음성 서버 (GPT-SoVITS)

옵션 화면에 **음성 서버 주소**를 넣으면 브라우저 내장 음성 대신 그쪽을 쓴다.
「목록 불러오기」로 목소리를 받아 고른다. 비우면 내장 음성을 쓴다.

**서버가 없거나 실패하면 조용히 내장 음성으로 떨어진다** — 소리가 아예 안 나는 것이
제일 나쁘다.

### 왜 별도 기계인가

우리 서비스가 쓰는 GPU 와 다투지 않는다. 실측에서 GPU 경합은 OCR 지연을 **13배**
흔들었다 (`DEVLOG.md`). 어차피 상시 대기 중인 서버가 있다면 거기가 맞다.

### 실측 (일본어, RTX 5080 별도 기계)

| 원문 글자 | 합성 | 오디오 길이 |
|---|---|---|
| 8 | 0.6초 | 1.5초 |
| 18 | 0.8초 | 3.1초 |
| 40 | 1.9초 | 7.6초 |

**RTF 0.25** — 재생이 합성보다 4배 느리다. 그래서 지금 것을 재생하는 동안 다음 것을
미리 합성해 두면 말풍선 사이가 끊기지 않는다 (한 칸만 앞서면 충분하다).

### 오디오를 data URL 로 돌려주는 이유

Blob URL 은 만든 워커의 수명에 묶이는데 MV3 서비스 워커는 30초 유휴로 죽는다 —
재생 도중 URL 이 무효가 된다.

### 합성 요청도 background 가 한다

콘텐츠 스크립트가 직접 부르면 **페이지 출처**로 요청이 나가 TTS 서버에 CORS 헤더를
붙여야 한다. background 에서 부르면 확장 출처라 그럴 필요가 없다 (`/read` 와 같은 이유).


## 만화 사이트에서 자동으로 켜기

옵션 화면의 **「자동으로 켜질 사이트」** 에 적은 호스트에서는 「자동」이 알아서 켜진다.
기본으로 comic-walker · yanmaga · shonenjumpplus · sunday-webry · comic-fuz ·
comic-growl · ichijin-plus 가 들어 있다. 한 줄에 하나씩 고치면 된다.

뒤에서부터 맞춘다 — `yanmaga.jp` 는 `www.yanmaga.jp` 에도 걸리고,
`yanmaga.jp.evil.com` 같은 위장에는 안 걸린다.

**두 조건을 다 만족해야 켜진다:**

1. 호스트가 목록에 있다
2. **뷰어로 볼 만한 요소가 실제로 있다** — 자동은 화면을 캡처해 서버로 보내는
   동작이라, 목차 페이지에서 돌면 헛돈다. `probeViewer()` 가 폴백(뷰포트 전체)으로
   떨어지면 뷰어가 아니라고 본다

뷰어는 대개 늦게 그려지므로 0.8초 · 2초 · 4.5초에 나눠 확인한다. 첫 시도에 없다고
포기하면 지연 로딩하는 사이트에서 영영 안 켜진다.


## 자동 실행에는 사이트 권한이 필요하다

`chrome.tabs.captureVisibleTab` 은 **`activeTab` 이나 그 사이트의 host permission**
이 있어야 한다. 그런데 `activeTab` 은 **사용자가 확장을 직접 실행할 때만** 주어진다
(아이콘 클릭·단축키). 자동으로 켜지면 그게 없어 캡처가 막힌다.

그래서 옵션 화면에서 **「저장」** 을 누르면 사이트 목록의 호스트 권한(`*://yanmaga.jp/*`
등)을 같이 요청한다. 허용해야 자동 실행이 된다. 거부해도 `Alt+Shift+M` 으로 직접
실행하는 것은 그대로 된다.

## 음성은 Web Audio 로 재생한다

`new Audio(dataUrl)` 을 쓰지 않는다. 그건 리소스 로드라 **페이지의 CSP(media-src)**
를 타는데, 만화 사이트는 CSP 가 빡빡해서 `data:` 오디오가 막힌다 — `onerror` 만 나고
"오디오를 못 읽었다" 로 끝난다.

background 가 base64 바이트를 주고, 콘텐츠 스크립트가 `decodeAudioData` 로 디코드해
재생한다. 스크립트 동작이라 CSP 를 타지 않는다.
